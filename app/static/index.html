Research Desk

Live market news, read into ranked trade ideas.

Company profiles and headlines come from yfinance. A System One model turns them into typed judgments — exposure, mechanism, direction, grounding — and code does the ranking and the routing.

Five stages, four of them judgments

  1. TriageSix questions per story in one request: market-moving (Noul), event type (Choice), magnitude (Score), horizon (Choice), unconfirmed rumour (Noul), and whether the text tries to instruct the reader (Noul). Code gates on the probabilities — that last one is a prompt-injection guard that rides along at no extra cost.
  2. ExposureOne Score per watchlist name plus one Choice, all in the same request. Six names cost one call, not six: the state is read once and every question is answered against it.
  3. MechanismThe transmission mechanism is selected from a catalogue code owns, never written freehand, so it is always one of nine known values. Four Nouls probe the link: evidenced, direct, priced in, near-term.
  4. GroundingCode assembles the thesis from judgments already returned, then a separate request checks it against the story. Probabilities land in a YES / UNCLEAR / NO band code draws, rather than the model electing an "unclear" token.
  5. CompositionPure arithmetic. Weights, thresholds and routing live in code, so re-weighting costs nothing.

Where uncertainty goes

Choice and Score answers carry a confidence derived from their distribution; a Noul near 0.5 means the model genuinely cannot separate yes from no. The desk routes on both, so an idea with a sound thesis but a weak strongest-mechanism confidence goes to review rather than publish.

Honesty

Profiles, prices and headlines are live and shown as retrieved; the desk does not clean up what Yahoo returns. Every threshold in desk/questions.py is a starting guess, not a value fitted to real outcomes. With a noisy live feed many runs produce one publishable idea or none — that is the filter working. Nothing here is investment advice.

Recording a run

Append ?autorun=1&pace=700 to the URL. Pacing inserts a pause between stages so the funnel is followable on camera; it never changes how the work is done, and the reported wall clock has the pauses subtracted back out. The header shows paced whenever it is on.
